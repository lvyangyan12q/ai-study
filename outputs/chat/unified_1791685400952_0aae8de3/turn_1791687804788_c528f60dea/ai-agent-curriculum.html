把"会用 Agent"升级成
能系统设计与调优 Agent

你已经天天在用 agent 了，缺的不是"怎么调 API"，而是一张把上下文、工具、记忆、协作、评估、训练串成因果链的地图——知道每个环节为什么这样设计、失效时该往哪里看。这份课件按主线教材《深入理解 AI Agent》（bojieli/ai-agent-book，★53.4k）的十章骨架重排为四个层级，每一层都配一个可动手的交互实验。

00怎么用这份课件

它不是一个"读完就完"的文档，而是一张会被你反复回来查的地图。

① 先看地图，再看细节

下面的知识地图是主干。点任意模块，右侧会显示它解决什么核心问题、难在哪、配套资源、以及"怎样才算学会"。

② 抽象概念先玩实验

上下文预算、ReAct 循环、工具时序、RAG 召回、评估噪声、多 Agent 上下文——这些光看文字会玄，交互实验室里拖一下滑块就明白了。

③ 用验收标准打勾

每个模块都写了"能独立做到 X"才算过。勾选会存在浏览器本地，顶部进度条随之增长。

本课件的假设（如果不符，告诉我，我按你的情况重排）：你有实际调用/编排 agent 的经验并会用 Python；目标是把原理吃透、能独立设计并诊断 agent 系统（而不是三天做出 Demo）；节奏按每周 6–8 小时、总长约 14 周设计，可整体缩放。

01知识地图：四层结构

Agent = LLM + 上下文 + 工具。所有模块都在回答同一个问题的不同侧面：如何让有限的信息处理能力，表现出可靠的行为。

内核层 · 决定能力上限 系统层 · 决定能做什么任务 闭环层 · 决定能否持续变好 横切层 · 决定规模下的表现

02推进路线：五个阶段

顺序不是随意的：先把"信息如何进入模型"搞懂（阶段一），你后面读任何框架源码都会快一个数量级；评估放在中途而不是最后，因为它本身就是调试工具。

03两周一个小节：节奏模板

每一小节都走同一个四步循环——这就是把"读过"变成"掌握"的机制。点开看每周具体做什么。

关于时间：若每周只能投入 3 小时，把"读"和"实验"合并、跳过源码精读，总周期拉长到约 24 周即可，不要删掉阶段三（评估）——它是最容易被跳过、也最影响你判断力的一环。

04自测：12 道判断题

这些题故意设计成"凭直觉容易答错"。选完立刻给解析，答错不扣分，但请想清楚你原来为什么选错。
